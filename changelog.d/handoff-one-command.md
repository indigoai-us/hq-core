`/handoff` now runs its mechanical steps with one command, `hq core handoff run`: the scoped knowledge commit, finalize, the detached post, auto-file and the builder route check, in that order, stopping at the first failure. Step 7 calls `hq core handoff archive-decision`. The skill no longer starts the `handoff-knowledge-commit.sh`, `handoff-finalize.sh`, `handoff-autofile.sh`, `handoff-builder-route.sh` or `handoff-archive-decision.sh` helpers; the helpers stay in place for now. Both commands first ship in hq-cli 5.345.228, which `requiresHqCli` in `core/core.yaml` already requires. `core/scripts/ci/rewrite-core-callers.mjs` gains a `COMMAND_FLOORS` table for `hq core` commands with no single helper twin (`handoff run` and `handoff archive-decision`, both 5.345.228), and `--check` now fails with `file:line` when a caller runs one of them above the install floor. Tests: `core/scripts/tests/handoff-launcher.test.sh`, `core/scripts/tests/handoff-knowledge-commit-scope.test.sh` and `core/scripts/tests/rewrite-core-callers.test.mjs` (the floor table, finding the calls, and `--check` red at 5.345.221 and green at 5.345.228). The skill calls it through `core/scripts/handoff-run.sh`, which passes every argument to `hq core handoff run` and passes its result through. hq-cli 5.345.231 rejects `--company` and `--deficiencies-json` with `Unknown arg` before any thread is written; when the CLI writes no thread, the wrapper finishes with the `core/scripts` helpers, which accept both flags, and reports `cli_fallback` in the JSON.
