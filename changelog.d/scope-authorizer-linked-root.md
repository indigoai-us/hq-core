Fixed (scope authorizer, company Outposts): a lane or shell session on a company Outpost no longer gets "Session has no company_slug bound" for the company it is bound to. The shell user's `~/hq` is a real directory whose `.claude`, `core`, `.codex` and `companies` are links into the shared install at `/opt/hq-company-jobs`, and its sessions are written under `~/hq/workspace/sessions`. `mandatory-scope-authorizer.sh` took its HQ root from its own physical location, `/opt/hq-company-jobs`, and looked for the binding in that root's workspace, which the shell user cannot read. The hook now reads the session binding (capability, `meta.yaml`, parent inheritance) from `CLAUDE_PROJECT_DIR` when that directory's `.claude/hooks` is the running hook's folder and its `core`, `companies` and `.codex` are the install's own. Every library, `companies/` match, manifest, skill and cache read still comes from the install root the hook finds from its own location. A root where the project directory is the install itself, as on a laptop or a personal Outpost, resolves as before. Tests: `scope-authorizer-linked-root.test.sh` builds the Outpost layout and checks that the bound company is readable, that other companies and unbound sessions stay blocked, that a project directory with its own hook copy, a copied `core`, its own near-empty `companies`, or a planted capability library cannot supply a binding, and that a plain root is unchanged.
