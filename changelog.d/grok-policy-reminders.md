Policy reminders now reach the model in Grok Build sessions. The policy hook used to skip PostToolUse for Grok, and it recorded SessionStart, UserPromptSubmit and PreToolUse policies as shown although Grok discards what a hook prints on those events, so no injected policy reached a Grok session. Tool-triggered policies are now returned as PostToolUse `additionalContext`. On the events Grok does not deliver, the hook holds the reminder without recording it, and the Grok adapter returns the held text with the next tool result of any tool; a policy is recorded as shown only when its text was returned. Held text is capped at 8,000 bytes (`HQ_POLICY_HELD_MAX_BYTES`) and is returned only when it fits under Grok's 10,000-character limit next to the other context of that tool result. Held text is removed, unrecorded, when the session ends, and a compaction purges the ledger copies kept with it. Nothing is held when Grok supplies no session id. The hold variables are read only under `HQ_HARNESS=grok`; Claude Code and Codex output is unchanged.
