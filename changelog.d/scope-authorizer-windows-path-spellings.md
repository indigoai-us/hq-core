Changed (hooks, Windows): on Windows (OSTYPE msys, cygwin or win32) the scope authorizer reads a drive path (`C:\folder\file`, `C:/folder/file`), a long-path form (`\\?\C:\folder`), an administrative share and a path that starts with one backslash as the folder the shell spells `/c/folder/file`, for Read, Edit, Write, NotebookEdit, Grep, Glob and Bash, and for the working directory. Each tool call now gets the same answer whichever way its path is spelled. A device path or a drive letter with no slash after the colon (`C:name`) is not accepted in a path field; spell the full path. A name with a trailing period or space is read as Windows opens it (`folder.` is `folder`), and a short 8.3 name for `companies` or a folder in it (`COMPAN~1`) is not accepted. macOS and Linux are unchanged. Tests: mandatory-scope-authorizer-windows-paths.test.sh.
