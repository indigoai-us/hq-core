Fixed (Work Mesh SessionStart, macOS): a SessionStart that reuses the cached offline preflight result now restores the session state file and the board. `35-work-mesh-session-start.sh` ran `chmod 600 -- FILE.tmp && mv ...`; BSD chmod reads a `--` after the mode as a file name, prints "No such file or directory" and exits 1, so the `mv` never ran and `sessions/<id>.json.tmp` and `sessions/<id>/board.md.tmp` were left in place of the real files. GNU chmod accepts the form, so Linux was not affected. Every chmod in this hook now goes through a helper that passes no `--` and puts `./` in front of a path that starts with `-`. Tests: `work-context-real-launch.test.sh` repeats the cache hit with a chmod on PATH that rejects `--` after the mode, as BSD chmod does, and checks the restored state and board, their 600 modes in a 700 folder, and that no temporary file is left, so the Linux CI run covers the macOS behaviour.
