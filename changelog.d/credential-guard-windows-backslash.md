Changed (hooks) the bash credential guard on Windows (Git Bash, MSYS, Cygwin) to read a backslash as a directory separator. Read and cat of a credential file named with backslashes, mixed separators, a drive letter, a drive-relative C:name, a \\?\ or \\.\ prefix, a UNC path, a trailing dot or space, or an NTFS default-stream suffix (::$DATA) now get the same refusal as the forward-slash spelling. A drive-relative directory given to a recursive reader or an archiver (grep -r 'C:..', tar 'C:Users\me') is checked both as C:\x and as x under the cwd; cd and pushd follow C:\x, as the MSYS and Cygwin runtime does. An administrative share (\\host\c$\x) is read as the drive path C:/x. A file URL (file:///C:/x, file:///C|/x, file://localhost/C:/x, file://127.0.0.1/C:/x, file://C:/x and the one-slash file:/C:/x) is read as the drive path too, and a file URL with another host (file://host/c$/x) is read as the UNC path //host/c$/x. A root-relative \x or /x\y, and a /x operand or Read path (which a native program opens as C:\x), is also checked at the root of the cwd's drive, ".." in a Windows path stops at the drive root (C:\..\Users is C:\Users), a wildcard after any of these spellings is expanded in each reading, and quotes inside a drive word (C"":x) no longer skip the full check. The payload cwd and a Windows HOME are folded the same way, and a drive path is shown in the shell's own spelling (/c/... on Git Bash and MSYS, /cygdrive/c/... on Cygwin), so the refusal message names one path. macOS and Linux still treat a backslash as a literal character. Tests: core/scripts/tests/credential-read-guard-windows-backslash.test.sh, run on Linux, stock macOS Bash and Windows Git Bash.
