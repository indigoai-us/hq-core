Fixed company job runs that stop on a provider usage or spend limit. They were recorded as `session_failed` with "provider failed (exit 1)". They are now recorded with error code `usage_limit`. The run reason quotes the provider's limit line and gives the reset time when the provider prints one. For a spend limit, the reason says to raise the spend limit and does not give a reset time. Claude's limit lines on stdout are covered, and so is Codex's usage-limit line at the end of its stderr, after the banner and the prompt echo. Another service's limit line, such as a mail or search API quota, stays `session_failed`. In a provider error line kept as the run reason, links now show as `[link]` and token-like strings are removed, while file paths are kept.
