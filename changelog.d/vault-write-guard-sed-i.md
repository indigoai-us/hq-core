The Bash vault write guard no longer blocks `sed -i` on a file outside the vault when the shell sits in a read-only company folder. It used to report "Vault path: sed" for scripts containing `;`, `|` or `&`, for `sed -i ''` and for `sed -i -l N`, because it read the word `sed` (or the script) as the file being edited. It now takes the file operands after the script and options, including `-i.bak`, `--in-place=SUF`, combined flags such as `-Ei`, and `-e` and `-f` scripts, and checks the operands that follow a quoted script the command splitter cut apart. Edits of a read-only vault file that were not blocked before are now blocked: `sed -E -i`, `sed -s -i`, `sed -ni`, `sed -i` or `--in-place` after the file, `--in-place=SUF`, abbreviated `--in`, BSD `-I`, `gsed`, `awk -i inplace` with other options first or with the program in `--source=PROG`, `-W source=PROG` or an abbreviated long option such as `--sour=PROG`, and `perl -pi` or `ruby -pi`. Escapes inside `$'...'` words are decoded before option names are read, so `sed $'-\x69'` and `awk -i inplace -W $'sour\x63e=PROG'` are blocked too. A quoted file name that contains `;`, `|` or `&` is now checked in full.
