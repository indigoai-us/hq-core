The held policy reminder store used in Grok Build sessions no longer writes through links. The policy hook used to append held reminder text and copy ledger rows with shell redirection, so a symlink or hard link planted at `<session>.held/out`, at a ledger copy, at the `<session>.held` directory or at the policy state directory sent that text to another file, and handing out the held text could read another file into the model's context. The hook now uses the held store only when the state directory and the held directory are real directories owned by the current user and every held file is a regular file with one link; new held files are created with noclobber. A refused store is removed (or left in place under a symlinked state directory), the reminder of that event is dropped without being recorded as shown, and one line goes to stderr. The hook's allow or deny result does not change. The compaction purge no longer removes files through a symlinked held or state directory. Handing out the held text and reclaiming a stale ledger lock now rename into a new directory the hook creates, so a link planted at a fixed claim or stale-lock name is never followed. On Linux, a held file that vanishes during the link-count check is skipped instead of refusing and removing the store.
