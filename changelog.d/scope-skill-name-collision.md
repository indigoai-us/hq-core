The scope guard no longer refuses a core skill because a company has a skill of the same name. A Skill call loads when the HQ skills folder or the user-level skills folder has a real folder of exactly that name, which covers core skills, pack skills, personal skills and your own user-level skills. Before this, an install where a company folder held a copy of the core skills had every one of those skills refused in sessions not bound to that company. Personal skills (`personal:<name>`) are also no longer treated as skills of a company named `personal`, and their copies under `.claude/skills` are readable again. A name addressed to another company (`<slug>:name`), or a name only another company's skill carries, is still refused outside that company.
