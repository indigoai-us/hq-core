Fixed the company job runner refusing an additional company Outpost. `validateConfig` now accepts an `opc_` Outpost id in the exact ULID form the server generates, as well as the first Outpost's `outpost_<companyUid>` id, and `acceptedJob` requires a job's `agentUid` to equal the box's own Outpost id, so each box runs only the jobs assigned to it. A first Outpost behaves as before. Regression tests in `core/scripts/tests/company-jobs.test.mjs` cover both id forms, malformed ids, and jobs owned by or targeted at another Outpost of the same company.
