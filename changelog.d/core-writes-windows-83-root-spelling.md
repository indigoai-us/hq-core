Fixed (block-core-writes, Windows): a plain write to `core/`, `.claude/` or another protected path is blocked again when the file path and the HQ root spell the same folder differently, one with its long name and one with its 8.3 short name (for example `C:/Users/runneradmin/...` and `C:/Users/RUNNER~1/...`). The guard read the file as outside the HQ root and allowed the write. When either path holds an 8.3 name and Git Bash's `cygpath` is present, both are now rewritten in long form before the checks run; a not-yet-existing tail is kept as written. Nothing changes on macOS or Linux. The Windows-only tests now fail, rather than skip, when a precondition is missing on a Windows CI runner.
