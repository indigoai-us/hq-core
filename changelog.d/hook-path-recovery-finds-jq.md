Fixed (hooks): a jq installed outside the inherited PATH no longer leaves every tool call blocked. Since v16.0.47 the dispatcher fails closed on PreToolUse when jq is missing after PATH recovery, but the recovery stopped as soon as node, hq and qmd resolved and only added folders that held those three tools. A jq in `~/.local/bin`, Homebrew, scoop or chocolatey was never found, and neither was the jq that `winget install jqlang.jq` (the fix the block message suggests) puts in `%LOCALAPPDATA%\Microsoft\WinGet\Links` or its package folder, because a Claude Code session opened before the install keeps the old PATH. Recovery now also looks for jq, checks both winget locations on Windows, and appends folders found only for jq to the end of PATH so the user's node, hq and qmd keep priority. A machine with no jq at all is still blocked, as before. Tests: `core/scripts/tests/hook-gate-path-augment.test.sh` cases 9 and 10.
