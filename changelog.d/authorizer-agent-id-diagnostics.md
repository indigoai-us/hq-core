The scope guard's "This call has an invalid agent_id" denial now says where the id came from (the hook payload or the `HQ_HOOK_AGENT_ID` environment variable), whether the payload itself names an agent, and what was wrong with the value: its byte length and the rejected characters as hex codes. The value itself is never printed. As a defensive change, the guard no longer matches a NUL pattern when it reads `agent_id` from the payload; it finds a NUL by code point instead. No jq build is known to misread the old pattern: jq 1.6, 1.7.1 and 1.8.2 were tested and behave correctly. A malformed non-empty `agent_id` is still denied.
