Added (update): the hq-core source address is configurable. `/update-hq` and the SessionStart update check (`.claude/hooks/check-hq-update.sh`) now read it from `HQ_CORE_SOURCE`, a JSON object with optional keys `repo`, `stagingRepo`, `apiBase`, `codeloadBase` and `webBase`, through the new resolver `core/scripts/lib/hq-core-source.sh`. When the env var is unset the resolver reads `~/.hq/core-source.json` (same shape). Every missing key keeps its GitHub default (`indigoai-us/hq-core`, `indigoai-us/hq-core-staging`, `https://api.github.com`, `https://codeload.github.com`, `https://github.com`), so nothing changes without an override. Invalid JSON or an invalid field prints one warning and uses the default for that field. gh and GitHub tokens are used only when the API host is `api.github.com`; any other host, such as `https://git.example.test/api/v3`, gets a plain request with no GitHub credentials. The `/update-hq` metadata read before an applying run now goes through `bash core/scripts/lib/hq-core-source.sh core-yaml`. Tests: `core/scripts/tests/hq-core-source.test.sh` (defaults, full and partial env override, trailing slashes, invalid JSON and invalid fields, http only for localhost, file fallback and env precedence, no parser, metadata read for default, staging and `--source`, no gh call, Authorization header or GitHub token for a non-GitHub host, update check on default, repo override, non-GitHub host and invalid JSON).
