Fixed (vault write guard): more ways to write a read-only vault file from Bash are now blocked. A `\'` inside `$'...'` (and a backslash-escaped quote outside quotes or inside `"..."`) no longer ends the word, so the paths after it are checked; `$$'` is read as the PID followed by a plain quote. A quoted in-place flag (`sed '-i'`, `sed $'-i'`, `awk -i 'inplace'`, `perl -p$'i'`) is read as an in-place edit, and a quoted command name in command position (`'rm' x`, `env 'rm' x`, `then 'rm' x`, `-exec 'rm' x`) as that command; a quoted search word such as `grep 'rm' x` is not. A `companies/` prefix spelled with `$'...'` escapes (`$'\x63ompanies/...'`) is checked as a vault path; commands whose escapes are only `\n`, `\t` and the like keep the fast exit. Regression tests in `core/scripts/tests/enforce-vault-write-access.test.sh`.
