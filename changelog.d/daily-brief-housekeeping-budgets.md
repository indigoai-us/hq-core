Fixed (daily-brief): housekeeping no longer stops its checks before they can finish on a large HQ tree, and each of its files now has one writer. The time budgets are now 150s for `hq doctor`, 480s for `hq sync now` and 60s for the worktree scan (were 40s, 30s and 20s). Each check's record is written into `housekeeping.json` as soon as it ends, with `state` and `pending` showing the checks still running, so the brief uses the early checks and never waits for the sync. `housekeeping.py` no longer writes `status.json` (the brief writer owns it and reads housekeeping state from `housekeeping.json`), never replaces a file it cannot parse, and copies the writer's proposals from the new writer-owned `housekeeping.proposals.json` into `housekeeping.json`; `housekeeping.py --merge-proposals` does that copy on demand, so proposals saved after the checks end still arrive. Every write of the housekeeping file takes an exclusive lock on `<file>.lock`, without blocking and retried for a bounded time (5s for the merge, which then exits 2 with "merge skipped"); where the lock file cannot be opened or locking is not supported, the check loop warns once and writes without it, while the merge exits 2 and leaves the copy to the next check write. New `--out` (only lower-case `housekeeping.json` or `housekeeping-<section>.json` in the run dir, never a symlink) lets person mode write one housekeeping file per section, so a late sync result lands where it is read. `hq sync now` now gets `--max-runtime` (the budget less 20s, or no flag when the budget is shorter than 40s), so the CLI stops the sync itself and records a failed pass before the hard kill; its exit 124 is recorded as "skipped (took too long)", and any other error exit stays "failed".
