Added (worktrees): an opt-in twig backend for code-repo dev worktrees. `core/scripts/worktree-backend.sh` is now the one place HQ creates worktrees: the `/worktree` skill, `/run-project` (`ensure_worktree`, `ensure_missing_repo_worktree`, per-story worktrees) and pipeline lanes (`add_worktree` in `pipeline-conductor.sh`) call it. The new setting `worktrees.backend` in `core/settings/worktrees.yaml` ships as `git`, which runs plain `git worktree add` as before. Setting it to `twig` in `personal/settings/worktrees.yaml` (or `HQ_WORKTREE_BACKEND=twig`) uses `git twig new` (git-twig 0.3.0+), which makes worktrees with copy-on-write on macOS APFS and Linux Btrfs/XFS. HQ falls back to plain git without failing when twig is missing or too old, on Windows, when the repo is one twig cannot copy (conversion attributes, submodules, autocrlf, sparse checkout), or when twig errors. The helper filters HQ's own post-index-change and reference-transaction dispatcher stubs out of the hooks path for the twig call, because twig refuses its copy-on-write path when those hooks exist. Removal stays `git worktree remove`. With twig on, each create is logged to `workspace/reports/twig-soak/events.jsonl`; `core/scripts/twig-soak-summary.sh` writes a daily summary. Docs: `core/docs/hq/worktree-backend.md`. Tests: `core/scripts/tests/worktree-backend.test.sh` (setting off uses git, setting on uses twig, base other than HEAD, existing-branch and detached modes, missing, old and failing twig fall back, ineligible repos skip twig, hook-stub filtering, env override, removal of twig-made and git-made worktrees); `run-project-regression-gate.test.sh` loads the new run-project function.
