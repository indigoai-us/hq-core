Fixed company job receipts so a failed run says why. A secret the broker refuses (HTTP 403) is still `blocked` with `secret_denied`; every other broker failure is now `blocked` with `secret_unavailable` and keeps the HTTP status, the broker's error code or the network error class, where every broker error used to read `secret_denied`. A broker answer with no value, a failed precondition, a job session that exits non-zero and a timeout now carry a short reason with the exit status and the last error line, with granted secrets and token-like strings removed. Runs with outcome `complete` record `succeeded` as before.
