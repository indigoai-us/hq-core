The Bash arithmetic guard now refuses a variable used without double quotes as a command when the same command changes IFS so that the value would split into a command and its arguments (for example `IFS=:; C=bash:-c; $C ...`), and it checks the command run by `env`, `sudo`, `doas`, `xargs`, `exec`, `nice`, `time`, `nohup`, `timeout`, `stdbuf`, `setsid`, `chroot`, `ionice`, `caffeinate`, `taskset`, `unbuffer`, `flock`, `watch`, `script`, `strace`, `arch`, `gtimeout` and `sandbox-exec` (also by any path, with short, attached or long options) the same way, including words those commands take before the command (option values, a timeout duration, a lock file), and refuses `env -S`, `flock -c` or `script -c` command lines that hold an expansion it checks a plain command (`C="bash -c"; env $C ...` is refused). IFS given only as a prefix of `read`, `mapfile`, `readarray`, `printf` or `echo`, as in `while IFS= read -r line`, does not count as a change, and a double-quoted `"$C"` after one of these prefixes stays allowed.
