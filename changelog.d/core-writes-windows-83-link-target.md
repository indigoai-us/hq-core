Fixed (block-core-writes, Windows): a write through a package contribution link (`core/knowledge/public/<pack>` -> `core/packages/<pack>/knowledge/<pack>`) is blocked again when the link's absolute target and the HQ root spell the same folder differently, one with its long name and one with its 8.3 short name (for example `C:/Users/RUNNER~1/...` and `C:/Users/runneradmin/...`). The guard compared the two spellings as plain strings, decided the link left `core/`, and allowed writes into installed pack content. It now also compares both in long form, case-insensitively, when Git Bash's `cygpath` is present. Nothing changes on macOS or Linux. Tests: `block-core-writes-package-mount-83.test.sh` (Windows shell smoke) covers long and 8.3 targets with long and 8.3 roots, and checks that an absolute link out of `core/` is still allowed.
