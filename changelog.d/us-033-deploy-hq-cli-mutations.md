Changed (deploy, project-summary): `/deploy` and the project-summary deploy step create apps, set password, private, company and selected gates, upload static sites, re-read gate state and take apps down with `hq deploy create|password-gate|private-gate|access|upload|inspect|takedown` instead of their own curl and `deploy_request` copies (US-033). Personal decks use `--personal`. The password reaches the CLI through an owner-only temp file, never argv. A missing `hq` stops before any call with `hq_cli_missing`. In `/deploy`, a company gate that `hq deploy access` cannot set now stops the deploy instead of falling back to a password gate. A selected-members gate sets the exact audience: `/deploy` reads the saved policy with `hq deploy access get`, removes members no longer in the audience in the same `access` call, and fails if the saved list does not match afterwards, so redeploying to a smaller audience revokes the dropped members. Needs an hq-cli release with these commands; until then those steps fail closed and nothing is uploaded. Calls with no CLI command yet (paged app list, app and SSR uploads, secret bindings, comments, database enablement) still use `deploy-api-request.sh`.
