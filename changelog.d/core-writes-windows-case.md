Fixed (block-core-writes, Windows): a protected write whose file path and HQ root differ only in letter case (for example `C:/hq/CORE/scripts/x.sh` with the root `C:/hq`) is blocked. Windows file systems ignore case, but the guard compared paths case-sensitively and allowed the write. On Git Bash every path comparison in the guard is now case-insensitive; the always-writable `.claude/settings.local.json` and `.claude/personal-context.md` match in any case too, and the `HQ_BYPASS_CORE_PROTECT` value is still matched exactly. The 8.3 long-name rewrite now looks up only a path that holds a short name, and refuses the write when that lookup fails, so a failed lookup can no longer leave the file path and the root in different spellings. Nothing changes on macOS or Linux. Tests: `block-core-writes-case-windows.test.sh` (Windows shell smoke).
