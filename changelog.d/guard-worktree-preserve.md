Added three guards against committing a copy of an HQ root into a code repository (incident a1227963, 2026-11-05): `core/scripts/worktree-preserve.sh` is the one flow that commits and pushes a dirty worktree before removal, with a file-count ceiling, an HQ-root marker denylist (`core/settings/worktree-preserve-denylist.txt`) and the commit secret scan, never `--no-verify`; `core/scripts/push-guard.sh` runs as a `pre-push` stage of the HQ git hooks (on wherever `commit-secret-scan.sh enable` is on) and rejects pushes that add marker paths or more than 2,000 files; and the PreToolUse hook `block-no-verify-bulk-add` blocks `git commit --no-verify` and `git push --no-verify` (it does not block `git add -A` with `git push` in one command). Policy `hq-worktree-preserve-uses-shipped-script`. Run `bash core/scripts/commit-secret-scan.sh enable` once after updating to refresh the hook stubs.
